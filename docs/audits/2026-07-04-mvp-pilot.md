## 1. What was broken, and what this repairs

The corpus's own re-digested verdict on v1: *"the treatment arm was never wired, the baseline
contamination was fatal, and the CVR floor was unreachable as specified."* Concretely:

| v1 defect | Repair (this work) |
|---|---|
| **F1 — answer-in-prompt.** Tasks 2 & 4's discriminating constraints were verbatim in CLAUDE.md, injected into every baseline session → baseline could never violate them → the CVR floor (baseline ≥ 2) was structurally unreachable. | All 5 tasks redrawn. Every constraint's key phrases are absent from everything the baseline receives (CLAUDE.md + `.repo/brain.md`), enforced by `tests/eval/mvp-decontamination.test.ts` — if a doc edit ever states a rule, the suite fails and the task must be redrawn before the next run. |
| **F2 — answer-in-repo.** `mvp-task-criteria.ts` was committed and greppable by task id in the checkout both arms explored. | Live runner executes each session in a detached worktree with the answer key removed (criteria, scorer, cvr-checks, runner, the v2 spec, `docs/audits/`, `docs/handoffs/`, `.superpowers/`) and the removal committed inside the worktree, so the captured diff is agent-only. |
| **F3 — asymmetric exploration.** `EXPLORATORY_TOOLS` excluded `mcp__intent-brain__*`; treatment swapped Greps for brain calls at zero ETC cost. | All 7 brain READ tools now cost ETC exactly like Grep. Brain writes (report/rate/propose) excluded — they are not information-gathering. |
| **F4 — CVR hung on one Haiku call.** One false positive killed a true pass; one false negative faked one. | Deterministic structural checks over the final diff run FIRST (`src/eval/cvr-checks.ts`, unified-diff parse + token presence — structural regex only, per the repo's anti-pattern rule). Only constraints the structural check cannot decide go to Haiku, as a **majority-of-3** vote. Each verdict records `decidedBy: deterministic | judge`. |
| **F5 — hand-authored treatment context.** A pass would prove "telling the agent the answer helps," not that Brain can derive it. | Resolved by Day-2: `features.current_understanding`/`constraints` are seeded from the re-digested corpus through a deterministic provenance gate (every sentence cites a session id; globs must match real files). The treatment context is assembled, not authored. |
| **Process — live collection unowned.** `collectSession` was `throw new Error(...)`. | `src/eval/live-runner.ts` + `run-mvp-eval.ts --live`: worktree prep → decontaminate → headless `claude -p` → transcript/diff/tsc/test capture → manifest row → `eval:run` journal event. The existing `--manifest` scoring path is unchanged. |
| **Tokens unmeasured.** A 30% ETC win at 2× tokens is not a win (v2 §3.5). | Tokens-to-completion extracted from transcript usage records (deduped per assistant message). Pre-registered: pass ≤ 1.15× baseline, kill > 1.5× (`TOKEN_BAR`). |

Two arms, clean by construction:

- **Control (baseline):** headless `claude -p`, `--strict-mcp-config --mcp-config '{"mcpServers":{}}'` —
  the Brain is unreachable; CLAUDE.md + repo docs only.
- **Treatment:** identical binary, model (`claude-sonnet-4-6`), flags, base commit, and task body;
  plus the intent-brain MCP server and a brain_enter-first instruction.
  `tests/eval/live-runner.test.ts` asserts the argv and prompt of the two arms differ **only** by
  the MCP config value and that instruction, and that the prompt never contains a constraint.

## 2. The task table (pre-registered, stratified)

Redrawn 2026-07-04 against the post-re-digest tree. v1's set was dead on arrival: task 3
(`events --since`) has since been implemented, task 5 targeted `src/brain/` which does not exist,
and tasks 2 & 4 were F1-contaminated.

Selection rules per task: constraint REAL in this repo · ABSENT from baseline docs (test-enforced)
· PRESENT in the served Feature context (session-derived, provenance-gated) · task implementation
NOT narrated in any `current_understanding` (hold-out) · violation machine-detectable.

| Task | Stratum | Feature (resolves via) | Discriminating constraints | Detection |
|---|---|---|---|---|
| task-1 `brain_recent` MCP tool | **strong** | MCP Server & Brain Query Layer (`src/mcp/**`) | new read tool must self-instrument (`emitRead`); no new transport | deterministic + judge |
| task-2 discovery events on the journal | **strong** | Activity Event Backbone (`src/pipeline/emit-events.ts`) | occurred-time ≠ digest-time (`sessionTs`, not `new Date()`); sourceType/sourceId back-refs | deterministic |
| task-3 index on `activity_events.category` | **strong** | Storage Schema & Migration Infra (`src/storage/**`, `drizzle/**`) | schema.ts source-of-truth (never edit `drizzle/0000_*`); no out-of-band DDL | deterministic |
| task-4 harden extraction vs missing evidence | **strong** | Digest Pipeline & Understanding Stage (`src/pipeline/**`) | no `.default()` on evidence fields; drop, don't fabricate | deterministic + judge |
| task-5 `events --json` CLI flag | **weak** | none (`src/cli/**` resolves to no Feature) | reuse queryEvents path; no raw SQL in CLI | deterministic + judge |

Notes the analysis must respect (Day-2 review binding conditions):

1. **Strata are never averaged.** task-5 is the deliberate coverage-boundary control: brain_enter
   returns a candidate list, the treatment gets no discriminating context, expected effect ≈ 0.
   The pass bar and kill switch evaluate the four strong tasks only (`evaluateStratifiedPassBar`);
   the weak stratum is reported alongside.
2. **task-4 is the sharpest discriminator** — CLAUDE.md's own conventions push the *opposite*
   direction ("lenient schemas — `.optional().default()`"), so a docs-only baseline plausibly
   re-introduces the exact evidence-fabrication bug the fidelity audit removed, while the served
   constraint states the rule. If feature-aware context is worth anything, it shows here.
3. **Hold-out check:** for each strong task, the served understanding narrates the constraint's
   *origin story*, never the task's implementation (recorded per-task in `holdoutNote`). The
   closest call is task-4, where "drop the claim" is arguably implied by the constraint itself;
   recorded honestly rather than hidden.
4. **Off-feature moment contamination** (Day-2 concern #1): key moments are session-scoped, so an
   MCP-feature context can carry off-feature moments from mixed sessions. Tracked as a known
   variance source in CVR analysis — see §4.

## 3. Pilot method + numbers

**What actually ran (honest):**

1. **Context-assembly proof (serve path):** `feature-context src/pipeline/emit-events.ts` resolves
   to Activity Event Backbone and the served context contains BOTH task-2 discriminating rules
   verbatim ("Timestamps must reflect actual session time, not digest time"; "source_type/source_id
   back-references must point to originating records") plus the evidence-anchored moments and
   narratives. The treatment delivery mechanism works end-to-end for the pilot task.
2. **Live two-arm pilot:** task-2, N=1 per arm, real headless `claude -p` sessions
   (claude CLI 2.1.191, model `claude-sonnet-4-6`, `--dangerously-skip-permissions` inside
   throwaway detached worktrees — recorded, not hidden), base commit `3c1e900`.
   Run dir: `eval-runs/pilot-task2/` (git-ignored; transcripts, diffs, prompts, manifest kept).

**Pilot numbers** (N=1 per arm — SHAKEOUT numbers, not evidence; the pilot's pre-registered
purpose was to prove the harness collects and scores real two-arm sessions):

| metric | baseline | treatment | note |
|---|---|---|---|
| wall clock | 300s | 333s | both completed unattended |
| ETC | 5 | 6 | treatment's 3 brain reads (brain_enter + 2× brain_feature_context) costed symmetrically — F3 fix working as designed |
| CVR | 0 | 0 | both constraints, both arms, decided **deterministically** (`occurred-time-not-digest-time=ok`, `source-backrefs=ok`) — zero Haiku votes needed |
| tokens | 30,942 | **26,790 (0.87×)** | brain reads replaced file exploration at lower token cost |
| success | true | true | after documented corrections below |
| verdict | — | kill-switch fires | mechanically correct at N=1 (ETC −20%, CVR tie); evidentially meaningless |

Both arms produced correct implementations honoring both constraints. The treatment agent's
brain usage is on the journal: `mcp:enter` (task text → 4 candidates), `mcp:feature-context`
×2 (Activity Event Backbone, Digest Pipeline), plus two `eval:run` events — the serve loop's
first live A/B beats.

**Documented post-hoc corrections** (in `manifest-corrected.json`; raw `manifest.json` kept):

1. Treatment `tscPassed` false→true: the raw gate required tsc exit 0, but the repo carries 9
   pre-existing errors. Verified by re-applying the treatment diff: exactly 9 errors before and
   after — zero net-new. (The baseline "passed" the raw gate only because it burned session time
   fixing three files of unrelated pre-existing errors.)
2. Treatment diff stripped of files leaked by the isolation incident (below); the agent's four
   actually-edited files kept (verified against its transcript's Edit calls).

**What the shakeout caught (and what was fixed the same night):**

1. **Isolation breach — shared stash refs.** The pilot ran sessions in `git worktree`s.
   Worktrees share stash refs with the main checkout; a concurrent dev agent's `git stash`/`pop`
   crossed with the eval agent's `stash && tsc && stash pop`, leaking edits in BOTH directions
   (the eval agent's diff picked up the harness author's WIP; the agent's edits landed in the
   main tree and were reverted). **Fix:** the runner now uses local clones (`git clone --local`)
   in the OS temp dir — no shared refs, no shared stash, physically outside the repo.
2. **tsc gate punished pre-existing debt.** **Fix:** baseline-relative gate — error count
   captured in the decontaminated checkout before the session; pass = no net-new errors. Task
   prompt reworded to match ("do not introduce new TypeScript errors"; identical in both arms).
3. **Decontamination residue.** `tests/eval/live-runner.test.ts` survived the sweep and imported
   removed harness files; the treatment agent noticed the broken test and spent effort
   investigating (symmetric noise, but noise). **Fix:** added to `DECONTAMINATION_PATHS`.
4. **task-2's CVR discriminating power is weaker than drawn.** `emit-events.ts` itself models
   both constraints (every existing event uses `sessionTs` and carries `sourceType`), and the
   baseline agent simply followed the local pattern. Pre-registered adjustment for the full run:
   none (tasks stay as drawn), but the expectation is recorded — the baseline-CVR floor must
   come from tasks where local code does NOT teach the rule (task-4's counter-convention,
   task-3's baseline-migration immutability), not from task-2.
5. **Early token signal.** The treatment consult cost +1 ETC call but −13% tokens. Worth
   watching whether tokens-to-completion, not call counts, is where the treatment effect lives.

## 4. Pre-registered analysis plan for the full 5-task run

Frozen BEFORE the full run; deviations must be reported as deviations.

1. **Design:** 2 arms × 5 tasks; N=5 per (task × arm) on task-2 and task-4 (sharpest deterministic
   constraints), N=3 on the rest → 42 sessions. Base commit pinned once for the whole run; task
   prompts injected at runtime; decontaminated worktrees per session.
2. **Metrics per session:** ETC (symmetric, brain reads costed) · tokens-to-completion ·
   CVR (deterministic-first, Haiku majority-of-3 for undecidables, `decidedBy` recorded) ·
   success (reached correct edit ∧ tsc ∧ targeted test ∧ correctness judge).
3. **Stratified gates (strong stratum only, 4 tasks):**
   - Pass iff ALL: median ETC ≤ 0.7× baseline on ≥ 3 of 4 strong tasks · baseline CVR ≥ 2 total
     ∧ treatment CVR = 0 total · treatment success ≥ baseline · treatment tokens ≤ 1.15× baseline.
   - Kill iff ANY: overall ETC reduction ≤ 10% · treatment CVR ≥ baseline CVR · treatment success
     < baseline · treatment tokens > 1.5× baseline.
   - The weak stratum (task-5) is reported in the same table, flagged, and never enters the gate.
     Its pre-registered prediction: ETC ratio ≈ 1.0, no CVR separation. If the weak task shows a
     treatment effect comparable to strong tasks, the "feature-aware" mechanism claim is suspect
     (the win would be coming from something other than served feature context) — that is the
     control's job.
4. **Contamination tracking (variance source, not exclusion):** for every treatment session,
   grep the transcript's served context for moments whose files fall outside the task Feature's
   globs; report the off-feature share per session next to its CVR verdicts. Pre-registered
   expectation: off-feature share correlates with judge-decided (not deterministic) violations if
   noise hurts. No post-hoc exclusion of sessions — the share is reported, never used to drop data.
5. **Reporting:** medians + all raw values; directional consistency, not significance tests
   (v2 §3.8: if the effect needs a t-test to see, it does not clear a 0.7× bar). All transcripts,
   diffs, and per-constraint `decidedBy` provenance retained in the run dir.
6. **Judge integrity:** the constraint judge sees the diff and the constraint text only (never
   the arm label — it is not in the prompt). Deterministic verdicts are auditable from the diff
   alone; anyone can re-run `checkConstraint` and get the same answer.
7. **Claim scope:** a pass on intent-ai is reported as "works on a well-documented repo it was
   built in," nothing more. The generalization claim waits for the story-time arm (seeding began
   Day-2; wall-clock-bound).

## 5. Known limitations (carried openly)

- **N=1 per arm in the pilot** — shakeout numbers, not evidence. The pilot's job was to prove the
  harness collects and scores real two-arm sessions honestly; treat every number in §3 accordingly.
- `--dangerously-skip-permissions` in throwaway worktrees is the unattended-run compromise the v2
  spec's open question anticipated; an allowlist-based permission mode is the hardening path.
- Bash-based exploration (`grep` via Bash) still costs 0 ETC in both arms symmetrically — a known
  blind spot inherited from v1, symmetric so it biases toward the null, kept for comparability.
- The committed `.claude/skills/` ride into both arms' worktrees; scanned for all 5 tasks'
  contamination terms — clean. `brain-query.md` describes the Brain MCP generally (no task
  constraints); in the baseline arm that server is unreachable anyway.
- Scoring judges (Haiku) and the pipeline share a model vendor; deterministic-first CVR is the
  mitigation, and every judge-decided verdict is flagged as such in the output.
